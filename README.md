# OneClip

必要なところを集めて、ひと貼りで伝えるmacOSのメニューバーアプリです。
一箇所をすぐコピーする操作と、複数箇所を一枚にまとめる操作を用意しています。

現在は開発中です。単発コピーとまとめ撮りは実装済みですが、安定性・使いやすさの確認（M4）は未完了です。
手動アップデートに対応しています。初回は[GitHub Releaseの0.2.0](https://github.com/TaigaShinohara/OneClip/releases/tag/v0.2.0)からアプリを配置し、以後の新しい公開版をメニュー・設定から確認できます。
ソースは[MIT License](LICENSE)で提供します。

## できること

- **範囲をコピー**：一つの画面内で範囲を選び、PNGをクリップボードへコピーし、自動保存します。
- **集めてコピー**：1〜4枚を撮影順に縦へ並べ、一枚のPNGとしてコピーします。小画像での素材確認、追加、個別削除、新旧比較後の撮り直し、拡大プレビューに対応しています。コピー後も現在のまとめを修正・再コピーできます。
- **撮影後のプレビューと注釈**：単発撮影とまとめ完成時に右下へ小画像を8秒間表示します。「コメント・記号を追加」から、画像上へ吹き出しコメント・四角囲み・手書き囲み・番号を置け、色も選べます。「保存してコピー」で注釈を一枚のPNGに焼き込み、AIへの指示や不具合報告に貼り付けられます。
- **手動アップデート**：メニューまたは設定の「アップデートを確認…」から、公開版を確認します。更新のダウンロード後、保存・撮影処理が終わった状態で「更新して再起動」へ進めます。起動時や定期的な自動確認・自動インストールは行いません。
- **任意のショートカット**：単発とまとめ撮りを別々に設定・変更・解除できます。初期値は未設定で、メニューだけでも使えます。
- **キーボードでの範囲調整**：矢印で移動、Shift＋矢印で大きさを調整し、Enterで確定、Escで取り消します。

コメントは日本語の複数行、配置後の移動・書き直しに対応し、注釈の削除・元に戻す・やり直す、全体表示・100%表示を使えます。撮影原本は変更しません。切り抜きなどの詳細編集には、メニューから保存画像の編集用コピーをmacOSの「プレビュー」で開けます。標準「プレビュー」で編集した画像は、自動では再コピーしません。OCR、AIへの直接接続・送信、ログイン時の自動起動は未実装です。

## 使い方

1. アプリを起動します。初回の使い方案内で、メニューバーの入口と二つの撮影を切り替えて確認できます。確認したモードだけを既読にし、まだ見ていない撮影の案内は最初の操作時に表示します。
2. 画面上端のOneClipメニューから、一箇所なら「範囲をコピー」、複数箇所なら「集めてコピー…」を選びます。
3. 必要に応じてmacOSの画面収録を許可し、「範囲を選ぶ」で進みます。単発では範囲確定後にコピーと自動保存を行います。右下の小画像を閉じたり、そのまま消えるのを待ったりしても保存画像は残ります。
4. まとめ撮りではパネルの「追加…」で素材を集め、素材と完成画像を確認して「コピー」を押します。完成PNGをコピー・自動保存し、右下へ表示します。個々の素材を集めている間はコピー・保存しません。拡大表示からもコピーボタンを使えます。拡大中のEnterではコピーしません。
5. 画像内に指示を書く場合は、小画像の「コメント・記号を追加」を選びます。画像上でコメントの位置を選び、右側の本文欄に入力して「コメントを適用」を押します。四角・手書き囲みはドラッグ、番号はクリックで置けます。色パレットから色を変更できます。
6. 「選択」で既存の注釈を選び、移動・本文変更・しっぽ先端の微調整・色変更・削除ができます。コメント適用後や囲み描画後は自動で「選択」モードに切り替わります。「保存してコピー」で注釈入りの別PNGを保存し、同じPNGをクリップボードへ渡します。その後、AIなどの入力欄へ自分で貼り付けてください。日本語変換中は先に変換を確定します。
7. 小画像が消えた後も、メニューから最新画像の注釈と保存フォルダを開けます。編集中なら同じ編集画面へ戻ります。閉じた後は、最後に保存した画像へ新しく注釈を付けます。注釈入りPNGを開き直した場合は、既存の文字や記号は画像の一部となり、個別に再編集できません。再起動後は保存フォルダから画像を開いてください。

起動や使い方の閲覧だけでは撮影・許可要求・コピーは行いません。案内はメニューや設定の「使い方…」から見返せます。
画面収録の設定から戻ると許可状態を再確認しますが、自動で撮影は再開しません。許可を確認できた後も、範囲選択は明示的に始めます。
範囲選択中のEscはコピーせず取り消します。追加・撮り直しを取り消した場合は、既存の素材を残します。
撮り直しの画像は確認用の候補です。現在の素材と切り替えて確認し、「候補を採用」で置き換えます。Escは候補だけを破棄し、現在の素材を残します。

まとめ撮りの通常パネルを閉じるかEscを押すと、素材を保持したまま隠れます。メニューの「集めた素材を編集…」から戻れます。
取得・合成中の閉じる／Escは処理の取消を要求し、実際の終了まで待ちます。書込み中と取消終了待ちには閉じられません。
コピー後も現在の素材を保持し、同じまとめへ明示的に追加・削除・撮り直し・再コピーできます。
コピー後に素材を変えていなければ、次のまとめ撮り入口・キーは新しいまとめを始めます。同じまとめに追加する時は「追加」を使います。
「新しいまとめを開始」や「まとめ撮りの編集を終了」では、未コピーの素材・コピー後の変更・未採用候補がある時だけ破棄を確認します。

収集の待機中でも「範囲をコピー」で単発コピーを使えます。集めた素材は変更しません。
単発の処理や未コピー画像が残っている間は、収集の追加・編集・コピーを停止し、理由と回復先を表示します。未コピー画像の確認待ちでは、収集素材の閲覧・非表示・明示的な編集終了もできます。単発の結果画面で再コピーするか破棄すると、まとめ撮りの編集へ戻れます。

設定を開いたまま撮影でき、選んだ範囲に設定画面があれば画像へ含めます。
ショートカットを変更している間は撮影を停止します。候補を確定するか取り消すと再開できます。
設定を含む範囲の取得中に設定窓が移動・閉鎖された場合は、撮影を中止して選び直しを案内します。

## アプリの更新

通常はOneClipメニュー、または設定の「アップデートを確認…」を使います。設定には現在のバージョンとbuild番号を表示します。「公開版」は通常の配布チャンネル名であり、M4の品質確認完了を表すものではありません。

設定の「開発用」を開くと、「開発版を確認…」からその回だけ開発中の版も候補に含められます。次の通常確認は公開版だけに戻ります。現在の開発版より古い公開版へ自動で切り替えることはありません。

未保存の画像・コメント・収集素材がある場合も、確認だけは行えます。適用は保存や編集の確定後に行い、撮影・画像処理・確認ダイアログの途中では待機します。更新情報の取得失敗や未公開の状態を「最新版」とは表示しません。

更新機能がない既存アプリには、最初だけ更新機能入りのアプリを手動で配置する必要があります。公開用の署名・公証済みアプリは[GitHub Releases](https://github.com/TaigaShinohara/OneClip/releases)から取得できます。製品版同士の実更新は未実証です。仕組みと公開手順は[手動アップデート](docs/UPDATES.md)を参照してください。

## データの扱い

単発撮影のPNGと、まとめ撮りで完成コピーするPNGを、アプリのサンドボックス内にある `Application Support/OneClip/Captures` へ自動保存します。メニューから保存フォルダを開けます。保存先を毎回選ぶ操作はありません。コピーと保存の結果は別々に扱い、保存できなかった場合もコピーの成否と区別して案内します。
保存中、または保存失敗の画像が残っている間は、次の撮影・完成コピーを停止します。失敗時はメニューから「画像の保存を再試行」か「保存せずに続ける」を選べます。終了時にも未保存画像を確認し、保存中は処理の完了を待ちます。
保存原本、注釈を焼き込んだPNG、標準「プレビュー」用の編集コピーは、プレビューを閉じた後、素材の破棄後、アプリの終了・ロック後も残ります。保存期限はなく、OneClipによる自動削除は行いません。必要のないファイルは保存フォルダで管理してください。設定と使い方の「保存とデータの扱い」からも説明を見返し、保存フォルダを開けます。
注釈の編集文書は一件だけをメモリ上で保持します。編集中と実際の読み込み・書き出しが終わるまでは、新しい撮影と収集素材の変更を停止します。未出力の変更がある時は閉じる前に確認します。注釈は100件、コメント一件は500文字、元に戻す履歴は100段階が上限です。本文が画像内に入らない場合は切り捨てず案内します。注釈と履歴の編集用データは終了・失効後に復元しません。
コメント・囲み・番号は説明用の注釈です。写った機密情報を隠す機能ではなく、撮影原本も残ります。送る画像に含まれる内容は、貼り付け・共有する前に確認してください。

収集セッション、選択範囲、操作履歴は保存せず、画面内容をログへ記録しません。画像・コメント・クリップボードの内容を外部送信しません。更新ボタンを押したときだけ、固定のGitHub更新フィードと配布ファイルを取得します。起動時の通信、定期確認、システムプロファイル送信は行いません。保存する設定は、単発・まとめ撮りのショートカットと、起動時・撮影時・初回コピー後の貼り付け案内の既読状態です。

まとめ撮りの素材は、コピー後も現在のまとめだけをメモリ上に保持します。次の新規開始、明示的な編集終了、アプリ終了、または失効まで修正・再コピーできます。パネルを隠すだけでは解放しません。過去版の画像履歴や、アプリ再起動後の復元はありません。
撮り直し候補は最大1枚です。採用・旧素材保持・次の撮り直し・編集終了・失効で候補を解放し、過去の候補を保存しません。
単発の取得画像はコピー成功でメモリ上の参照を解放し、右下の表示には縮小した小画像を使います。取得後の画像準備・書込みに失敗した時は再コピーまたは破棄まで保持します。保存済みPNGの寿命は、このメモリ上の保持とは別です。

公開通知や操作前後の再確認で、スリープ、ロック、ユーザー切替、画面構成変更、画面収録の許可喪失などの利用状態変化を検知した場合、メモリ上の保持画像を失効させます。保存済みファイルは削除しません。利用状態を確認できない場合も撮影・コピーを停止します。まとめ撮りでは破棄枚数・理由・コピー状態を文字の案内に残し、失効した画像は再表示しません。
すべてのロック経路の即時検知や、OSの状態確認と撮影・コピーを不可分にする保証はありません。処理の取消は画像処理にも伝えますが、処理中の画像は処理が実際に終わるまでメモリに残る場合があり、物理メモリの即時完全消去は保証しません。
注釈の読み込み・描画・PNG生成も、保持中の収集素材と合わせて同じ384MiBの画像バッファ予算へ含めます。単発とまとめ撮りが併存しても、画像バッファの見積りは合わせて384MiB以内へ制限します。プロセス全体のメモリ使用量を保証する値ではありません。

コピーするとmacOSのクリップボードを置き換えます。書込み時はこのMac内だけで使う指定を付けますが、クリップボード管理アプリや貼り付け先の保存・同期は制御しません。貼り付け先やOSによるクリップボードの扱いはOneClipの画像保存とは別です。
OneClipの素材を破棄しても、保存済みファイル、すでにコピーした画像、貼り付け先の画像を自動で消去することはありません。安全条件・確認方法・未実証範囲は[セキュリティ検証](docs/SECURITY-VERIFICATION.md)を参照してください。

## 開発環境とビルド

- macOS 14.0以上を対象とするSwiftUI / AppKitアプリ
- Xcode 16以上、Swift 6対応のツールチェーン
- 更新機能にSparkle 2.10.1をSwift Package Managerで完全固定。初回の依存解決にはネットワーク接続が必要
- Xcodeプロジェクト：`OneClip.xcodeproj`、共有scheme：`OneClip`
- Bundle ID：`local.OneClip`（ローカル開発用の暫定値）

新しいビルドを始める前に、実行中のビルド、メモリ、作業先と一時領域の空き容量を確認します。

```sh
ps -axo pid=,comm= | rg 'xcodebuild|swift-frontend|swift-build|GradleDaemon|ninja'
memory_pressure -Q
df -h . "${TMPDIR:-/tmp}"
```

`rg` の終了コード1は、一致するプロセスがないことを表します。
リポジトリ直下で次を実行すると、Appleアカウントや配布証明書を使わずコンパイルを確認できます。

```sh
ONECLIP_DERIVED_DATA="${TMPDIR:-/tmp}/OneClip-DerivedData"
xcodebuild -project OneClip.xcodeproj -scheme OneClip \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath "$ONECLIP_DERIVED_DATA" \
  -jobs 2 CODE_SIGNING_ALLOWED=NO build
```

起動確認にはXcodeのRun、または上の `CODE_SIGNING_ALLOWED=NO` を外したローカルのアドホック署名ビルドを使います。
通常のビルドに個人の認証設定は不要です。DebugだけLibrary Validationを無効にし、ローカルのアドホック署名でSparkleを読み込めるようにしています。この緩和はReleaseへ含めません。更新配布用ReleaseはDeveloper ID署名とnested codeの検証を必要とします。配布・公証は[手動アップデート](docs/UPDATES.md)の別工程です。

一部の取得失敗の原因は未確定です。公開文書の整理によって製品の未解決事項が解消したとは扱いません。

手動更新は実SDKでのuniversal Releaseビルド、関連Swift回帰172グループ、Python279件、専用テストアプリでの正常更新・再起動／不正署名拒否を確認しています。署名・公証・初回配布と公開ZIPの再取得も確認しています。製品版同士の実更新とUIの実操作は未実証です。[限定検証の詳細](docs/UPDATES.md#2026-11-02の限定検証)を参照してください。

検証の根拠と残件は [M0](docs/M0-VERIFICATION.md)、[M1](docs/M1-VERIFICATION.md)、[M2](docs/M2-VERIFICATION.md)、[M3](docs/M3-VERIFICATION.md)、[M4](docs/M4-VERIFICATION.md) を参照してください。

`Tests/` には架空素材や専用pasteboardを使う独立したCLI試験があります。座標計算の最小例は次のとおりです。
コンパイル前には上と同じ資源確認を行います。

```sh
ONECLIP_TEST_DIR="$(mktemp -d -t oneclip-tests)"
xcrun swiftc -swift-version 6 -strict-concurrency=complete -parse-as-library \
  -module-cache-path "$ONECLIP_TEST_DIR/module-cache" \
  OneClip/RegionGeometry.swift Tests/RegionGeometryTests.swift \
  -o "$ONECLIP_TEST_DIR/geometry"
"$ONECLIP_TEST_DIR/geometry"
```

実画面や一般クリップボードを使う確認は、架空素材の内部試験と分けて明示的に実行します。
画面・クリップボードの内容を不具合報告やGitへ含めないでください。

設定撮影・画像内注釈に関係する架空サービスの回帰試験は `bash scripts/test_settings_capture.sh` で実行できます。
各コンパイル前に実行中ビルド・メモリ・ディスクを確認し、別ビルドがあれば停止します。
実画面取得・画面収録の許可要求・一般クリップボードの操作は行いません。
