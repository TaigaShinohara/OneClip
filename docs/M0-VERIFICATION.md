# M0 限定試作の検証要約

この文書は限定試作で確認した技術上の結果と制約をまとめたものです。
現在の仕様と工程は[ROADMAP](ROADMAP.md)を参照してください。試作の成立を製品全体の動作保証には使いません。

## 対象

架空素材を使うDebug限定パネルで、画像合成・限定ウィンドウ取得・キー登録・クリップボード書込みの境界を確認しました。
当時の試作には、製品の範囲選択や収集セッションは含まれていません。

## 確認した結果

- 画像コアで1〜4枚の縦配置、番号、余白、1枚の場合の例外、寸法・画素・演算上限を確認しました。
- 対象ウィンドウを限定した単発取得と、表示更新後の架空内容の取得を確認しました。対象識別が一致しない場合は中止します。
- 取消・パネル閉鎖後の遅い結果を採用せず、実行中workerの完了まで処理枠を保持する経路を確認しました。
- 登録型ホットキーの検出、明示解除、パネル閉鎖時の解除を限定確認しました。
- 架空画像のコピー、別アプリでの新規貼り付け、アプリ終了後の再貼り付けを確認しました。
- 通常のアプリ切替では素材を保持し、ロックによる失効と新しい明示操作での再開を代表条件で確認しました。
- 内部試験には架空素材・差替え処理・専用pasteboardを使用しました。

## 限定完了の範囲

画像処理・取得・書込み・キー登録の方式を次段階で評価する根拠が揃ったものとして、M0は限定完了です。
任意の画面取得、製品の操作導線、全環境の権限遷移、全面的なアクセシビリティを検証済みとする判断ではありません。

<a id="m0-carryover"></a>
## 未実証と引継ぎ

- 製品の選択UI非表示と取得の同期、画素境界・色・異倍率・複数画面の厳密な確認。
- 未許可・拒否・許可後復帰・許可取消、および同一プロセス中の権限遷移。
- 一般pasteboardの別プロセス競合、書込み準備後の失敗、旧内容の保護限界。
- ロック・スリープ・ユーザー切替・処理中の失効の全経路。
- 任意ショートカットの設定・変更・衝突・終了時解除と、VoiceOverによる実操作。
- 最大負荷・反復・置換・PNGとプレビューを含むピーク資源量、対応OS・CPU・貼り付け先。
