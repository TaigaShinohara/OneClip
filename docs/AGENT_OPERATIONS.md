# OneClip 操作カタログ（Agent Operations）

OneClip を AI エージェントが GUI なしで操作・検証できるようにするための正本。
設計の考え方は `agent_friendly_app_design` スキルの後付け手順に従う。
機械経路の使い方は `docs/AGENT_GUIDE.md`、機械可読な目録は `docs/agent-manifest.json` を正とする。
カタログに無い操作を機械経路へ場当たりで足さない。先にここへ登録し、狙いを添えてから実装する。

- 監査日: 2026-11-24
- 対象版: OneClip 1.0.1 (4) / main
- 現在の到達レベル: **L0**（GUI のみ。下記「監査」参照）
- 目標レベル: **L1 ＋ 保存データ管理の書き込み（L2 の部分集合）**（理由は「目標レベルの判断」参照）

## 監査（現状把握）

| 項目 | 判定 | 根拠 |
|---|---|---|
| データの保存場所と形式 | 済 | 撮影画像は `~/Library/Application Support/OneClip/Captures/` に PNG ファイルで保存（`CaptureArchive`、ファイル名 `OneClip-<日時>-<UUID>.png`、注釈の編集コピーは `<元名>-edited-<UUID>.png`）。設定は UserDefaults（ガイド既読フラグ `OneClip.hasSeen*`、ホットキー `OneClip.singleCaptureHotKey.v1` / `OneClip.collectionCaptureHotKey.v1`）。収集セッションと注釈の編集中データはメモリ内のみで永続化されない |
| 業務ロジックの UI からの分離 | 済（混在箇所を特定） | 撮影・収集・注釈は Coordinator / Controller 層に分離されている。ただし撮影パイプライン（`ScreenshotService`、各 Coordinator）は AppKit / ScreenCaptureKit / クリップボードに依存し、ヘッドレスには実行できない |
| 外部から触れる経路 | 未 | CLI、URL スキーム、AppleScript、XPC のいずれも無い。起動引数には内部検証用フラグ（`--m0-self-test` 等）だけがある |
| ID の安定性 | 一部 | 保存ファイル名末尾の UUID は安定 ID として使える（再利用なし）。収集素材の ID はセッション内メモリでのみ有効。注釈は UUID を持つがデータとしては永続化されない（PNG へ焼き込まれる） |
| 実行履歴と失敗理由 | 未 | 永続化された履歴は無い。失敗は画面表示のみで、後から機械可読に確認できない |
| テスト基盤 | 済 | Swift テストスイート（`scripts/test_settings_capture.sh` 等、swiftc 直接コンパイル）と Python テストスイート（`Tests/*.py`）がある |
| スクリーンショット取得経路 | 未 | 自動化された画面検証（スクリーンショットテスト）は無い。検証は Mac 実機での手作業が正 |
| 秘密情報 | 済 | 画像内容・クリップボード内容・実画面をログや外部へ出さない設計（リポジトリ規約）。機械経路でも画像バイト列そのものは出力しない |

### 目標レベルの判断

スキルの既定目標は L2（主要操作を機械から実行できる）だが、OneClip の主要操作である撮影は次の理由でヘッドレス実行できない。

1. 画面収録の許可（TCC）は GUI アプリのプロセスに紐づき、許可ダイアログは OS が人間にだけ出す。
2. 範囲選択は人間のドラッグ操作そのものであり、撮影対象の指定が操作の本体である。
3. 撮影・収集・注釈の各 Coordinator は GUI セッション内の状態（前面アプリ、選択オーバーレイ、クリップボード所有）で動く。

そのため今回の到達点は **L1（読み取り可能）＋ 保存済みデータの管理書き込み（書き出し・隔離削除）** とする。
撮影系を機械化するには、アプリ内エージェントモード（起動中アプリへの XPC / ファイル受け渡し）という別工程が必要であり、
今回はカタログに「将来の経路」として登録だけを行い、実装しない。

## D18 / D19 の現行実装状態（照合結果）

2026-11-24 に `docs/ROADMAP.md` の記述と現行ソースを照合した結果。どちらも **仕様として採用済みだが、現行版 1.0.1 では未実装** であり、ROADMAP 自身もその旨を明記している（D18 / D19 の各行末尾と §末尾の注記）。

| 判断 | 内容 | 現行の実装状態 | 現行の実際の動作 |
|---|---|---|---|
| D18 順序の入れ替え | 収集素材は撮影順を既定とし、隣接同士の入れ替えだけを認める | **未実装**（GUI・機械経路とも） | 順序は撮影順で固定。順序ミスの回復は個別削除と撮り直しのみ |
| D19 保存失敗時の継続 | 保存に失敗した画像だけを「未保存」と識別して隔離し、撮影・収集変更・完成コピーは止めない | **未実装**（GUI・機械経路とも） | D15 の従来動作のまま: 保存失敗が未解決の間は撮影と収集変更を停止し、保存の再試行か明示破棄で回復する |

機械経路（今回の CLI）はセッション内状態を扱わないため、D18 / D19 の実装状態に影響しない。
両判断の実装は GUI 側の後続工程であり、このカタログの #14 が D18 の受け口になる。

## 人間専用操作の一覧（理由）

| 操作 | 理由 |
|---|---|
| 画面収録許可のダイアログ応答・付与 | OS の TCC ダイアログは本人にだけ出る。機械が代行できない |
| 範囲選択のドラッグ（単発・まとめ撮り） | 撮影対象の指定そのものが人間の身体操作 |
| ホットキーの記録（設定変更） | 実際にキーを押す対話的操作で確定する |
| アップデートの適用 | 置き換えと再起動を伴い、本人の同意が前提（Sparkle の GUI フロー） |
| 画質・見え方の最終判定 | 身体感覚の判定。機械は数値検証まで |
| App Store 提出まわりの操作 | 本人の明示承認が要る別工程。このカタログの対象外 |

## MCP / SDK の判断

- MCP: **今回は入れない**。スキルの順序どおり、L2（操作）と L3（検証）が GUI 連携まで含めて動いてから検討する。デスクトップ型は stdio ラッパーが素直であり、将来入れる場合は CLI コマンドと 1 対 1 対応のツールにする（`references/platform-patterns.md` のデスクトップ節）。
- SDK: **作らない**（既定どおり）。他の自作アプリからの再利用需要も、外部公開の方針も無い。代わりに JSON スキーマと `docs/AGENT_GUIDE.md` を正本として整える。

## CLI の共有範囲（正直な境界）

- CLI (`Tools/OneClipAgent/`) は、アプリ本体とは **保存形式の契約**（保存先、ファイル名の文法、PNG 署名の検証、安定 ID = ファイル名末尾の UUID、シンボリックリンクを辿らない読み取り）を共有する。
- アプリ本体の `CaptureArchive` は macOS のディスクリプタ / ACL API に依存するため、そのコード自体は CLI と共有していない。契約の同一性は契約テスト（`Tests/OneClipAgentContractTests.py`）で担保する。
- Xcode プロジェクト（アプリ本体・ストア提出構成）には一切手を入れていない。CLI は独立した SwiftPM パッケージであり、本体ビルドへ影響しない。
