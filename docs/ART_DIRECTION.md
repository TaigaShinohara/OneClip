# アート方針：OneClip

- 版：1.0
- 決めた日：2026-11-16
- 出どころ：既存実装（`OneClipStyle.swift`）およびコンセプト（`README.md`）からの導出
- 対象：アプリ全体の UI（設定、使い方案内、権限・確認ダイアログ、撮影後小画像、まとめ撮りパネル、注釈エディタ、アップデート画面）

## 1. 世界の言葉

- 雰囲気キーワード：静か、明晰（クリア）、誠実
- やらない雰囲気：騒がしい、過度な装飾、不透明（何をしているか・どこに保存されるか分からない）
- 一文で言うと：必要な瞬間にだけ静かに現れ、撮った・まとめた・伝えたがひと目で分かる、誠実な macOS ツール。

## 2. 根拠マップ（コンセプト → アートの選択 → 理由）

| コンセプトの要素 | アートの選択 | 理由 |
| --- | --- | --- |
| メニューバー常駐で必要な時だけ使う | 控えめな彩度、静かな背景色（`windowBackgroundColor` / `controlBackgroundColor`） | 作業中の他アプリの邪魔をせず、必要な瞬間にだけスッと馴染むため |
| 「範囲をコピー」と「集めてコピー」の2つの軸 | 役割別の2色（`single`: インディゴ系、`collection`: ティール系） | 2つの撮影モードを言葉だけでなく色でも即座に区別でき、誤操作を防ぐため |
| クリップボードや保存・権限の扱いを明示する誠実さ | 高い可読性、余裕のある余白、極薄の境界線と明確な `warning` トーン | 重要な案内や確認が埋もれず、安心して操作を判断できるため |
| 注釈やプレビューで画像そのものを伝える | 画像を主役にし、周囲の UI は無彩色・低彩度に抑える | ユーザーが撮った画像・書いたコメントが一番目立つようにするため |

## 3. 色の性格

- 主色（`single`）：単発撮影（「範囲をコピー」）および基本の主要アクションに使う。落ち着いたインディゴ系で、集中と即応を表す。
- 補助色（`collection`）：まとめ撮り（「集めてコピー」）の文脈で使う。落ち着いたティール系で、整理と連続性を表す。
- 中立色（`neutral`）：補助情報、注記、非強調のラベルに使う（`.secondary`）。
- 警告色（`warning`）：確認ダイアログ、権限不足、保存失敗、失効通知など注意が必要な場面に使う。落ち着いたアンバー系。
- 背景と文字の関係：macOS 標準の `windowBackgroundColor` / `controlBackgroundColor`（ダーク時は極薄の白オーバーレイ）を基調とし、システムの高コントラスト設定（`colorSchemeContrast == .increased`）時は境界線を強める。
- 色を増やすときの決まり：既存の4役割（`single`, `collection`, `neutral`, `warning`）で表せない明確な意味がある場合のみ追加する。
- やらない色使い：意味なく画面ごとに色を変える、画像を邪魔する高彩度な装飾色を使う。

※ 具体的な色値・トークンは `OneClip/OneClipStyle.swift` を正とする。

## 4. 形の言語

- 角丸の方針：Apple の連続角丸（`style: .continuous`）を使う。カードは `20pt`、小カード・ボタン・パネル内要素は `8〜12pt`、バッジは円形。
- 線と境界：原則として面（背景のわずかな明度差）と余白でグループを分け、境界線は極薄（通常 `0.035`、高コントラスト時 `0.45`）にとどめる。
- 影と立体：カードにのみごく控えめな影（`radius: 10, y: 3`、透明度 `0.035〜0.07`）を付け、浮きすぎない自然な階層を作る。
- アイコンのタッチ：SF Symbols（`.medium` ウェイト基調）。見出しバッジではトーン色の薄いグラデーション円背景に載せる。
- イラスト・写真：機能紹介の図解（`CaptureUsageDiagram`）に限り、アプリの世界観に合わせたシンプルな図形表現を使う。

## 5. 文字と密度

- フォントの性格：見出しは `.rounded`（`size: 20, weight: .semibold`）で親しみと明晰さを出し、本文・補助・操作ラベルはシステム標準フォントで可読性を優先する。
- 文字の階層の原則：主役（見出し / 主画像）＞ 補助（`.callout` / `.body`）＞ 注記（`.caption` / `.secondary`）の3段階を基本とする。
- 密度の方針：4 / 8 の倍数を基調に余白を取る（ウィンドウ `28pt`、カード内 `20pt`、見出し内 `16pt` / `7pt`）。詰め込みすぎず、呼吸できる余白を保つ。
- 1画面の情報量の目安：3秒で「何の画面で、次に何を押せばいいか」が分かる量に収める。詳細な説明や開発用設定は畳むか別画面へ逃がす。

## 6. 動きの性格

- 動きの性格：穏やかで控えめ。主役や状態変化（モード切替、小画像の表示、注釈の選択）を分かりやすく伝えるためにのみ使う。
- 動きを入れてよい場面：状態遷移のフィードバック、パネルや小画像の出現・消滅。
- やらない動き：飾りだけのループアニメーション、ユーザーの操作を待たせる演出。
- 動きを減らす設定への対応：macOS の「視差効果を減らす（`accessibilityReduceMotion`）」を尊重し、不要な移動・拡大縮小を避ける。

## 7. 良い例／悪い例

- 良い例：`CaptureSettingsView` / `CaptureGuideView` / `CapturePermissionContent` — `oneClipWindow`、`oneClipCard`、`OneClipHeading` を一貫して使い、主役と補助の階層が明確。
- 改善対象（ズレの棚卸し結果）：
  - `AppUpdateViews.swift`：`OneClipStyle` を未使用で、独自余白・独自レイアウトになっている可能性があるため確認・統一が必要。
  - `CaptureResultController.swift`（`CaptureResultView`）：右下の小画像プレビュー。`OneClipStyle` との角丸・影・境界線の一貫性を確認する必要がある。
